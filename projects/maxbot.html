MaxBot: Autonomous Delivery Robot

A team-built delivery robot. I wrote its motor control code and am now building a wireless emergency-stop remote with two ESP32-S3s.

  • ESP32-S3
  • C++ (Arduino)
  • PWM motor control
  • ESP-NOW
  • Safety systems

First iteration: drive test

I wrote the drive code for this first version. It controls two motor drivers, one per side:

  • Bidirectional control: each side has a forward and a reverse PWM input, and a single signed speed from −255 to +255 sets direction and power.
  • 20 kHz PWM: above the range of human hearing, so the motors don't whine.
  • Power cap: speed is limited to 180/255 to protect the drivetrain during testing.
  • Smooth ramping: speed changes one step every 5 ms instead of jumping, which avoids current spikes and wheel slip.
  • Test sequence: forward, stop, reverse, stop, spin left, spin right, which checks every motor direction and differential steering.

In progress: wireless E-stop remote

A delivery robot needs a reliable way to stop it remotely. I'm building a handheld remote with two ESP32-S3s, one on the remote and one on the robot, talking over ESP-NOW (a direct, low-latency ESP32-to-ESP32 radio link that needs no Wi-Fi network). Both prototype sketches work on the bench.

Remote (transmitter)

  • Three buttons: red = STOP (latching), white = SLOW, blue = NORMAL. A joystick gives manual driving.
  • Command rate: it sends a small command packet about 33 times a second. Each packet has a sequence number, the mode, an E-stop flag, and the joystick position.
  • Joystick handling: the joystick is calibrated at power-up and has a deadband, so it reads exactly zero at rest.
  • Debounced buttons, plus a link LED: fast blink while connecting, solid when linked, off when the link is lost.

Robot (receiver): designed to fail safe

  • Loss of signal = stop: if no packet arrives for 250 ms, the robot stops. A dead battery, an out-of-range remote, or interference all stop the robot rather than leave it running.
  • Re-arm required: after a lost link, the robot stays locked out until the operator presses STOP and then deliberately re-arms it, so it never takes off on its own when the signal returns.
  • Stale packet rejection: out-of-order or repeated packets are discarded using their sequence numbers.
  • Speed limits per mode: SLOW halves the top speed and turn rate.
  • Status LED: an RGB LED shows the state at a glance: yellow = no link, red = stopped, orange = locked out, blue = slow, green = normal.
